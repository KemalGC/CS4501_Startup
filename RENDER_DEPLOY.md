# Deploy the existing StrokeSense review study on Render

Status: code/configuration prepared. A connected Render account, actual service
creation, private study transfer and post-restart live verification are still
required. A GitHub commit or green test is not a live public website.

## Create the service with the Blueprint

In Render choose New > Blueprint, connect KemalGC/CS4501_Startup, select branch
`dev-consolidated`, and use `render.yaml` in the repository root. Review the paid
service/disk cost shown by Render before confirming. Do not create another
service if one is already being provisioned through the connected Render app.

The Blueprint creates one `0.5c-512mb` Python web service (formerly Starter), a
2 GB disk at `/var/data`, generated separate owner/reviewer secrets, and a
single Uvicorn process. Automatic deployments are OFF to avoid changing an
ongoing alpha study. It installs only `requirements-hosted.txt`, not the model
or analysis dependencies. Existing local launchers are unchanged.

Render supplies `RENDER_EXTERNAL_URL`; the gateway accepts that exact HTTPS
origin. No wildcard host/CORS and no trusting arbitrary forwarded hosts. A
custom domain needs `STROKESENSE_PUBLIC_ORIGIN` set to that exact HTTPS origin.
Only the Uvicorn port is public; the unchanged review handler is loopback-only.
Python 3.14.8 is selected. The two security codes are generated by Render, not
committed to GitHub. No payment or infrastructure is created merely by adding
this file or running the tests.

## Initialize the private study

When the service is reachable, open `/setup` on its assigned HTTPS address.
In the service Environment page, copy `STROKESENSE_OWNER_KEY` into the owner-key
field. Select the COMPLETE `StrokeSense-10-Video-Review.zip`, not an old updater
ZIP. Upload and wait for the page's explicit installed-clip count. This action
shares the selected footage with invited study participants; verify you have
permission to do so. Do not put media or private feedback in the public repo.

The server streams the ZIP to disk, validates paths and declared sizes, copies
only catalog-referenced media/reports, then atomically publishes `/var/data/study`.
Maximum ZIP750MiB, expanded content900MiB,2000archive members. It does NOT import
code, old owner keys or participant databases. It refuses replacement of an
initialized study, preserving any existing feedback. Failed validation removes
temporary files. Simultaneous setup is refused. This is not a database-migration
or existing-participant upload facility.

A healthy `/healthz` with `study_ready:false` means the server is alive but the
private study is NOT ready. Do not invite participants until it becomes true,
all expected clips appear, and playback, saving and restart persistence pass.
Large public uploads and the host's proxy limits still need actual Render
verification; this has not been tested against a live Render service.

If a large browser upload is rejected by the host, use Render's authenticated
SCP or shell-transfer instructions to transfer the same ZIP to
`/var/data/study-upload.zip`. In the service Shell run:

```sh
python -m strokesense.feedback_pack --archive /var/data/study-upload.zip --data-dir /var/data --permission-confirmed
```

Restart the service afterward. Remove only the temporary uploaded ZIP once the
study has been verified; never remove `/var/data/study/.feedback`. Do not run
shell installation concurrently with browser setup. Shell provisioning also
refuses overwriting an initialized study.

## Share with the five rowers

Share the service's `/library` HTTPS link and `STROKESENSE_REVIEW_CODE` with
participants. They enter the reviewer code, then the existing consent form.
Never share the owner key or owner dashboard URL. The access code is an
invitation barrier, not individual identity verification. Session cookies are
Secure, HttpOnly and SameSite=Strict. The signed access cookie expires after
seven days. Changing the reviewer code invalidates existing access cookies.

The original six aspect assessments and five overall-quality questions are
unchanged. Reports remain sandboxed. Video range requests allow seeking.
Private owner exports remain separately authenticated. Database, owner key and
assets live under the persistent disk. Existing LOCAL responses remain on the
old computer: initialization does not migrate them or count them as new users.

## Pre-invitation acceptance checklist

1. `/healthz` reports ready and the correct ten clips are visible after consent.
2. Test original/annotated playback, seek, and the correct report on a phone
   using cellular data, not just the deployment machine.
3. Save one aspect and all five quality answers, then restart the Render service.
4. Reopen the same browser session; verify saved answers and owner CSV/JSON.
5. Confirm an unauthenticated browser cannot fetch video or owner exports.
6. Withdraw the synthetic test session so it is not counted as a real rower.

Export backups after testing sessions. Do not rely only on whole-disk snapshots
for SQLite backups. Do not scale to multiple instances or multiple gateway
workers; the setup mutex, rate limits and private handler are per process.
The small paid service is for precomputed review, not video inference. Actual
Render bandwidth, large-upload behavior, availability and billing are not
measured by local/CI tests. A shared access code is unsuitable for a large public
service; this deployment is scoped to the five-rower alpha.

## Verification and primary documentation

`python -m unittest discover -s strokesense/hosting_tests -p 'test_*.py' -v`
checks exact origin, CSRF/invite/session/owner gates, streaming media, sandboxed
reports, persistence across app instances, withdrawal and rejected packages.
`python strokesense/hosting_tests/browser_hosted.py` uses an actual TLS Uvicorn
server and native Chrome with a self-signed TEST certificate and synthetic
media. Ignoring that test certificate is not a production TLS configuration.
