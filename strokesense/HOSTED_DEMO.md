# Hosted video demo and LLM feedback

The `strokesense-render-live` branch deploys the prepared-video demo to the
existing Render service. Its root `render.yaml` is the active Blueprint.

The website embeds `/demo`. Pressing **Run analysis again** runs pose tracking,
stroke segmentation, cadence estimation and technique measurements in a CPU
subprocess. After that process exits, a separate language-model process writes
coaching feedback from the saved `metrics.json`. The model does not inspect the
video or calculate the numerical measurements.

With `STROKESENSE_LLM_FEEDBACK=1`, the model is
`Qwen2.5-1.5B-Instruct-Q4_K_M`, executed locally through llama.cpp with two CPU
threads. The pinned official weights are SHA-256 verified before loading and
cached in `STROKESENSE_LLM_MODEL_DIR` on the existing persistent disk. No API key
or external inference service is required. Only the initial model download
uses the model host; report inputs stay on Render.

The report keeps its existing rower cards, numerical metrics, candidate flags,
charts and frame pictures. Its crew summary and per-rower observations and
technique suggestions are generated by the LLM. `llm-feedback.json` records the
model identity, generation time, token usage, input hashes and final HTML hash.
Output is validated before publication and is never substituted with fixed
text labelled as LLM output. A failed generation leaves the measured report
available and exposes a failed feedback status.

On deployment, an existing saved report is enriched without repeating pose
inference. Current feedback is reused only if its input, prompt and report
hashes still match. A fresh analysis always regenerates measurements and LLM
feedback. The service runs one pipeline at a time and retains its latest runs.

The first LLM run downloads roughly 1.1 GB of weights. Later runs use the cached
model. The current Blueprint keeps the existing 2 CPU / 4 GB service and 2 GB
disk allocation. The web worker stays available while analysis and feedback run
in the background.

Focused verification:

```bash
PYTHONPATH=. python -m unittest discover -s hosting_tests -p 'test_hosted*demo*.py'
PYTHONPATH=. python -m unittest discover -s hosting_tests -p 'test_hosted_llm_lifecycle.py'
PYTHONPATH=. python -m unittest discover -s tests -p 'test_llm_feedback.py'
```

These automated tests exercise lifecycle and validation with synthetic model
outputs. A deployment also needs a real model generation and a live report
check; passing the tests alone does not demonstrate working LLM inference.
